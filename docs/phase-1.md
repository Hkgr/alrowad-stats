# المرحلة الأولى — التأسيس وأول مقطع يعمل

## ما نُفّذ

**فحص التهيئة** (دون تغيير `.env` أو حذف بيانات):

| البند | النتيجة |
|---|---|
| اتصال قاعدة البيانات | يعمل — MySQL 8.4.7، الترميز utf8mb4، كل الجداول InnoDB |
| migrations | الجداول الأساسية سابقًا؛ أُضيفت أربع migrations جديدة بـ`php artisan migrate` (بلا `migrate:fresh`) |
| Sanctum | مثبّت وجدول `personal_access_tokens` موجود. لا مسارات محمية بعد (المرحلة 2) |
| `/api/v1/health` | يعمل |
| Vite proxy | `/api` ← `127.0.0.1:8000` يعمل |

الإصلاحات: تعديل `DatabaseSeeder` (كان ينشئ مستخدم اختبار يفشل عند إعادة التشغيل) ليستدعي مُدخِلات قابلة للإعادة؛ جعل أخطاء `/api/*` تُرجع JSON دائمًا؛ إضافة خط Cairo محليًا عبر `@fontsource-variable/cairo`.
ملاحظة غير معدّلة: `.env` يحوي مفاتيح مكررة (`QUEUE_CONNECTION`، `CACHE_STORE`) — آخر قيمة هي المعتمدة، وتركتها كما هي.

**النموذج** (انظر [data-model.md](data-model.md)): `institutions`، `sectors`، `projects`، `offices`، `periods`، `data_sources`، `measures`، `beneficiary_records` مع Models وعلاقات. مفاتيح أجنبية مركّبة `(institution_id, id)` تمنع في قاعدة البيانات نفسها ربط مشروع/مكتب/فترة بمؤسسة أخرى.

**الخلفية:** `BeneficiaryDashboardService` يحسب كل الأرقام (بطاقات، شارتات، جدول)؛ `FilterOptionsService` للفلاتر المتتالية؛ `InstitutionFiltersRequest` للتحقق؛ API Resources؛ ثلاث نقاط تحت `/api/v1` موثقة في [../api/README.md](../api/README.md).

**الواجهة:** لوحة عربية RTL بهوية كحلية وبرتقالية: شريط جانبي يمين قابل للطي (ودرج على الجوال)، رأس، شريط فلاتر مع الفلاتر النشطة وإعادة الضبط، أربع بطاقات، رسم أعمدة أفقي لترتيب المكاتب، حلقة توزيع الجنسين، أعمدة مكدسة، جدول قابل للبحث والفرز، قسم «نطاق البيانات ومصدرها»، ووضع العرض بملء الشاشة. حالات تحميل وفراغ وخطأ، وحركات خفيفة تُعطَّل مع `prefers-reduced-motion`. الفلاتر محفوظة في عنوان الصفحة.

## نطاق بيانات البداية

**مقطع واحد فقط** من ملف المشروع `data/raw/2026/لعبة و فرحة 2026.xlsx`: مشروع «لعبة وفرحة»، **أيار 2026**، سبعة مكاتب. **ليس استيرادًا كاملًا** لملفات المؤسسة لعامي 2025 و2026؛ الشهور الأخرى وسنة 2025 غير موجودة ولم تُخترع. صفوف الملف طابقت الجدول المرجعي في الطلب، والمُدخِل يرفض التشغيل إن اختلفت الإجماليات عن 718 / 732 / 1450.

**المسار (القطاع):** وجدتُ دليلًا موثّقًا في `data/Projects List_2026_09-29.xlsx` (ورقتا «مشاريع حسب الزمن» و«مشاريع حسب المكتب»): المشروع تحت «مسار الثقافة والرياضة والتسلية والفنون»، فأُسند إليه وحده من بين المسارات. عمود `level 1` («نشاط ترفيهي») حُفظ كما هو في `source_category` ولم يُعامل كمسار.
ملاحظة: حالة المشروع في ذلك الملف متضاربة بين الأوراق (On Hold / Closed)، ولم تُستعمل.

نوع القياس: **الاستفادات المسجلة** — وحدة: استفادة مسجلة لشخص؛ مستوى السجل: مشروع ومكتب وشهر؛ التجميع: مجموع. ليسوا «مستفيدين فريدين».

## ما بقي للمرحلة الثانية

- استيراد كامل لملفات `data/raw/2025` و`data/raw/2026` (بما فيها تعريف قياسات الملفات الأخرى وفق [data-model.md](data-model.md)) ثم إظهار الخط الزمني ونسب النمو عند توفر فترات قابلة للمقارنة.
- تسجيل بقية المسارات والمشاريع والمكاتب (حلب، إعزاز، جنديرس، إدلب…) من `Projects List`.
- المصادقة (Sanctum) وحماية المسارات، وإدارة المؤسسات والبيانات من داخل النظام.
- اختبارات واجهة آلية ضمن المستودع (اختبار المتصفح الحالي أُجري خارجه)، وتنظيف المفاتيح المكررة في `.env`.
- ملاحظة إدارية: الملفان `data/Projects List_2026_09-29.xlsx` وملف القفل `~$…` خارج `data/raw` فلم تشملهما قواعد `.gitignore` للبيانات؛ أضفتُ تجاهلًا لملفات `~$` فقط، وقرار إخفاء ملف قائمة المشاريع من Git لك.
